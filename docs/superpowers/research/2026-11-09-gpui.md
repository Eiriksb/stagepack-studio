## 2. Minimal bootstrap
Smallest real example: examples/hello_world/src/main.rs (Cargo.toml: `gpui-kit.workspace = true`, `[features] gpui-fast = ["gpui-kit/gpui-fast"]`). Verbatim:
```rust
use gpui_kit::component::button::*;
use gpui_kit::component::*;
use gpui_kit::*;

pub struct Example;
impl Render for Example {
    fn render(&mut self, _: &mut Window, _: &mut Context<Self>) -> impl IntoElement {
        div()
            .v_flex()
            .gap_2()
            .size_full()
            .items_center()
            .justify_center()
            .child("Hello, World!")
            .child(
                Button::new("ok")
                    .primary()
                    .label("Let's Go!")
                    .on_click(|_, _, _| println!("Clicked!")),
            )
    }
}

fn main() {
    gpui_kit::application().run(move |cx| {
        // This must be called before using any GPUI Component features.
        gpui_kit::init(cx);

        // Opens a window with a `Root` wrapping the view, so dialogs, sheets,
        // notifications and menus work in it.
        gpui_kit::open_window(WindowOptions::default(), cx, |_, cx| cx.new(|_| Example))
            .expect("Failed to open window");
    });
}
```
Facts (crates/kit/src/lib.rs): `open_window(options, cx, build) -> Result<(AnyWindowHandle, Entity<V>)>` wraps the built view in `base::Root::new(view, window, cx)` itself (lines 181-196), so you do NOT create Root manually; `init(cx)` calls `gpui_component::init` (theme + components, also gpui-base) (207-212). `application` = `platform::application` (200). `use gpui_kit::*` is all of GPUI (re-export of gpui or gpui_fast). The theme comes from `gpui_component::init`; `ActiveTheme`/`cx.theme()` in `gpui_kit::component`.
Linux X11 variant: see webview example below (`gpui_kit::platform::linux(WindowingModes::X11)`, then `.with_assets(gpui_kit::assets::Assets).run(...)` for the icon set). `WindowingModes` comes from `gpui_kit::*` (re-export of the gpui platform types); I did not locate its definition (it is in the gpui-pre-platform crate, not this repo).

## 3. gpui-webview
Repo example, examples/webview/src/main.rs, verbatim (identical at v0.9.0):
```rust
use gpui_kit::component::{
    ActiveTheme as _, IconName, WindowExt as _,
    button::{Button, ButtonVariants as _},
    h_flex,
    input::{Input, InputEvent, InputState},
    menu::{DropdownMenu as _, PopupMenuItem},
    v_flex,
};
use gpui_kit::*;
use gpui_webview::WebView;

pub struct Example {
    focus_handle: FocusHandle,
    webview: Entity<WebView>,
    address_input: Entity<InputState>,
}

impl Example {
    pub fn new(window: &mut Window, cx: &mut App) -> Entity<Self> {
        let webview = cx.new(|cx| {
            let builder = wry::WebViewBuilder::new();
            #[cfg(any(debug_assertions, feature = "inspector"))]
            let builder = builder.with_devtools(true);

            WebView::build(builder, window, cx).expect("Failed to create WebView")
        });

        let address_input =
            cx.new(|cx| InputState::new(window, cx).default_value("https://gpui-kit.com"));

        let url = address_input.read(cx).value().clone();
        webview.update(cx, |view, _| {
            view.load_url(&url);
        });

        cx.new(|cx| {
            let this = Self {
                focus_handle: cx.focus_handle(),
                webview,
                address_input: address_input.clone(),
            };

            cx.subscribe(
                &address_input,
                |this: &mut Self, input, event: &InputEvent, cx| match event {
                    InputEvent::PressEnter { .. } => {
                        let url = input.read(cx).value().clone();
                        this.webview.update(cx, |view, _| {
                            view.load_url(&url);
                        });
                    }
                    _ => {}
                },
            )
            .detach();

            this
        })
    }

    pub fn hide(&self, _: &mut Window, cx: &mut App) {
        self.webview.update(cx, |webview, _| webview.hide())
    }

    fn go_back(&mut self, _: &ClickEvent, _: &mut Window, cx: &mut Context<Self>) {
        self.webview.update(cx, |webview, _| {
            webview.back().unwrap();
        });
    }
    // go_forward identical with .forward()
}

impl Focusable for Example {
    fn focus_handle(&self, _cx: &gpui_kit::App) -> FocusHandle {
        self.focus_handle.clone()
    }
}

impl Render for Example {
    fn render(&mut self, _: &mut Window, cx: &mut Context<Self>) -> impl IntoElement {
        let webview = self.webview.clone();

        v_flex()
            .p_2()
            .gap_3()
            .size_full()
            .child(
                h_flex()
                    .gap_2()
                    .items_center()
                    .child(Button::new("back").ghost().icon(IconName::ChevronLeft)
                        .on_click(cx.listener(Self::go_back)))
                    // ... forward button, Input::new(&self.address_input), "more" dropdown_menu with Reload / About dialog
            )
            .child(
                div()
                    .flex_1()
                    .border_1()
                    .h(gpui_kit::px(400.))
                    .border_color(cx.theme().border)
                    .child(webview.clone()),
            )
    }
}

fn main() {
    // Required this for Windows to render the WebView.
    #[cfg(target_os = "windows")]
    unsafe {
        std::env::set_var("GPUI_DISABLE_DIRECT_COMPOSITION", "true");
    }

    // WebKitGTK embeds only into X11 windows, so use XWayland in a Wayland session.
    #[cfg(target_os = "linux")]
    let app = gpui_kit::platform::linux(WindowingModes::X11);
    #[cfg(not(target_os = "linux"))]
    let app = gpui_kit::application();

    app.with_assets(gpui_kit::assets::Assets).run(move |cx| {
        // This must be called before using any GPUI Component features.
        gpui_kit::init(cx);

        gpui_kit::open_window(WindowOptions::default(), cx, |window, cx| {
            Example::new(window, cx)
        })
        .expect("Failed to open window");
    });
}
```
(The elided middle of render is the Reload/About dropdown, lines 109-134 of the file.)

WebView API (crates/webview/src/lib.rs):
- `WebView::build(builder: wry::WebViewBuilder, window: &mut Window, cx: &mut App) -> wry::Result<Self>` (137-164): preferred. Linux: checks X11 window (errors on Wayland), initializes GTK and drives its loop from GPUI, with gpui-fast builds into a composition surface. Non-Linux: `builder.build_as_child(&*window)`.
- `WebView::new(webview: wry::WebView, window, cx) -> Self` (93): wraps a wry view you built yourself (no Linux GTK/X11 setup, so use `build`).
- Both are called inside `cx.new(|cx| ...)` to make an `Entity<WebView>`; render by `.child(webview_entity.clone())` in a sized div (WebView implements Render, lib.rs:350). Bounds are set automatically in the element's `prepaint` (`set_geometry`, 182-224); manual: `set_bounds(wry::Rect)` (168), `set_visible(bool)`, `show()`, `hide()`, `bounds()`, `visible()`.
- Other methods: `load_url(&str)`, `back()`, `forward()`, `set_theme(wry::Theme)`, `set_zoom(f64)`/`zoom()`, `raw() -> &wry::WebView` (evaluate_script, reload, url, open_devtools...), `handle() -> WebViewHandle` (Rc clone, UI-thread-local, `.raw()`); `Deref<Target = wry::WebView>`.
- Builder methods (wry = lb-wry 0.53.3 fork of tauri wry 0.53): with_url, with_html, with_ipc_handler, with_initialization_script, with_custom_protocol (all standard wry; docs/webview.md:103-112 table lists with_url/with_html, with_on_page_load_handler, with_navigation_handler, with_new_window_req_handler, with_ipc_handler, evaluate_script[_with_callback]). I did not read lb-wry's source to confirm with_custom_protocol/with_initialization_script signatures; they are standard wry 0.53 (`with_custom_protocol(name, Fn(WebViewId, Request<Vec<u8>>) -> Response<Cow<[u8]>>)`, `with_ipc_handler(Fn(Request<String>))`, `with_initialization_script(&str)`).
- IPC to a GPUI entity: NO repo example uses with_ipc_handler / with_initialization_script / with_custom_protocol (searched file tree + docs; github code-search API returned nothing, so confirm by grep after any checkout). The only guidance is website/docs/webview.md:112 and 130: page -> Rust is `with_ipc_handler(|request| ...)` receiving strings from `window.ipc.postMessage(...)`; "Do not capture &mut Window, &mut App, or &mut Context here"; "Pass status or IPC messages into application-owned state through a safe scheduling/channel path, then update the Entity on GPUI's context and call cx.notify()". Handler runs on the UI/GTK thread on Linux, but `Window/App` are not available, so the pattern to build is: handler pushes into `async_channel`/`futures::channel::mpsc` Sender (or std mpsc + polling), and `cx.spawn(async move |this, cx| { while let Ok(msg) = rx.recv().await { this.update(cx, |this, cx| {...; cx.notify()}) } })` in the owning entity. Rust -> page: `webview.read(cx).raw().evaluate_script("...")`.
- Windows: `std::env::set_var("GPUI_DISABLE_DIRECT_COMPOSITION", "true")` before starting GPUI (examples/webview/src/main.rs "Required this for Windows to render the WebView."; docs/webview.md:157 calls it "an example-specific requirement"). WebView2 on Windows: GPUI overlays (menus, dialogs, tooltips, popovers) CANNOT render above the page ("Windows: Not yet; the WebView covers overlays", crates/webview/README.md table; docs/webview.md:155,159) even with gpui-fast; partial clipping not supported (child extends past container). Workaround per docs: put overlays outside the webview rect or use a separate window. `gpui-fast` workspace dep also has `windows-manifest-provided-by-host` (Cargo.toml:75).
- Linux: X11/XWayland only; Wayland unsupported (README table; webview.md:69-91). Needs `libwebkit2gtk-4.1-dev`. With gpui-fast on Linux, GPUI overlays render above the page (needs compositing manager for shadows/backdrops; webview.md:63). Under fractional scaling the wrapper sets page zoom to GPUI scale / GDK_SCALE (webview.md:89). Clicks on the page are forwarded to GPUI on Linux so outside-click popovers close.
- Always keep one `Entity<WebView>`; never build in render; call `hide()`/`show()` when a tab stops rendering it (webview.md:97). Drop all `WebViewHandle`s before window destruction.

Small real test, crates/kit/tests/ui.rs (full, with helper crates/kit/tests/common/mod.rs `open_window` which calls `gpui_kit::open_window` with `WindowOptions { window_bounds: Some(WindowBounds::Windowed(bounds)), ..Default::default() }` and returns `(WindowHandle<Root>, Entity<V>)`):
```rust
mod common;
use gpui_kit::test::{TestSupportExt, TestWindowExt};
use gpui_kit::{
    AppContext, Context, Entity, Role, SharedString, TestAppContext, Window,
    component::{button::Button, input::{Input, InputState}},
    div, prelude::*, px, size,
};

struct Profile { name: Entity<InputState>, submitted: Option<SharedString> }

impl Render for Profile {
    fn render(&mut self, _: &mut Window, cx: &mut Context<Self>) -> impl IntoElement {
        let status = self.submitted.as_ref().map_or_else(
            || SharedString::from("Not saved"),
            |name| SharedString::from(format!("Saved: {name}")),
        );
        div().size_full().flex().flex_col().p_4().gap_4()
            .child(div().flex().flex_col().gap_1().child("Profile name").child(
                Input::new(&self.name).id("name").aria_label("Profile name").w(px(240.))))
            .child(Button::new("save").label("Save").on_click(cx.listener(|this, _, _, cx| {
                this.submitted = Some(this.name.read(cx).value());
                cx.notify();
            })))
            .child(div().id("status").role(gpui_kit::Role::Status).test_support()
                .aria_label(status.clone()).child(status))
    }
}

#[gpui_kit::test]
fn saves_a_profile_through_the_ui(cx: &mut TestAppContext) {
    cx.update(gpui_kit::init);
    let (handle, profile) =
        common::open_window(cx, Some(size(px(640.), px(480.))), |window, cx| {
            let view = cx.new(|cx| Profile {
                name: cx.new(|cx| InputState::new(window, cx)),
                submitted: None,
            });
            view
        });

    cx.update_window(handle.into(), |_, window, cx| {
        window.render_frame(cx);
        assert_eq!(window.find("status").role(), Some(Role::Status));
        assert_eq!(window.find("status").label(), Some("Not saved"));

        window.click("name", cx);
        window.input("Ada José", cx);
        let name = window.find("name");
        assert_eq!(name.label(), Some("Profile name"));
        assert_eq!(name.focused(), Some(true));
        assert_eq!(name.value(), Some("Ada José"));
        assert!(name.bounds().size.width > px(0.));
        window.press("backspace", cx);
        assert_eq!(window.find("name").value(), Some("Ada Jos"));

        window.click("save", cx);
        let status = window.find("status");
        assert!(status.visible());
        assert_eq!(status.label(), Some("Saved: Ada Jos"));
        assert!(status.bounds().top() >= window.find("save").bounds().bottom());
    })
    .unwrap();

    cx.update(|cx| {
        assert_eq!(profile.read(cx).submitted.as_deref(), Some("Ada Jos"));
    });
}
```

## Surprises / blockers
1. Published gpui-webview 0.9.0 lacks the Linux X11 abort-on-drop fix (commit dbb0b9a4, Nov 8; main adds gdkx11/x11 deps). Next release probably fixes it. Check before depending on tabs/panels that drop WebViews.
2. gpui is `gpui-pre` snapshot crates (exact `=0.3.11` pin), not crates.io `gpui`; API changes with weekly releases; pin `gpui-kit = "=0.9.0"` style. gpui-fast moves daily (0.1.14 today) but kit requires ^0.1.13, so cargo may float it; use Cargo.lock.
3. No MSRV declared; edition 2024 => >= 1.85; no problem with 1.98.
4. No IPC example in the repo; only docs guidance. WebView is "experimental".
5. Windows: webview covers all GPUI overlays (menus/dialogs/tooltips/color picker popovers over the page rect) and cannot be partially clipped, with or without gpui-fast; need GPUI_DISABLE_DIRECT_COMPOSITION=true. Linux with gpui-fast is OK. Native menu on Linux is just a GPUI fallback.
6. Wayland sessions must run through XWayland (`platform::linux(WindowingModes::X11)` is global for the app).
7. Code search via gh api returned nothing; "no example uses X" claims come from the file tree (4047 paths) plus reading the webview example/docs, not a full-text grep.
