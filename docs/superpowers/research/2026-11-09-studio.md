### Shape of a selection

```ts
// client/types.ts
export type SourceRange = [start: number, end: number]   // 2: [start, end), zero-based, relative to slide *content* (after frontmatter)

export type TargetKind =                                  // 4-16
  | 'heading' | 'paragraph' | 'list' | 'list-item' | 'quote' | 'table' | 'rule'
  | 'html' | 'component' | 'code' | 'frontmatter' | 'unknown'

export interface StudioTarget {                           // 18-43
  el: HTMLElement            // the rendered element picked
  no: number                 // slide number
  range: SourceRange | null  // resolved against real source; null = could not be traced (not editable)
  kind: TargetKind
  tag?: string               // source tag name for html/component targets
  prop?: string              // frontmatter key, for layout text marked data-studio-prop (range is null then)
  positioned: boolean        // has v-drag pos (directive or <v-drag> wrapper)
  nested: boolean            // shares its Markdown block with siblings
  label: string              // 'H1', 'Text', 'List item', '<Pill>' ...
}
```

What identifies an element: there is no stable ID. Identity is `(no, range)`, plus the DOM node. The
markdown-it plugin (`node/markdown-source.ts`) stamps rendered elements with `data-studio-src="start,end"`
(18), `data-studio-kind` (21), `data-studio-tag` (28), `data-studio-sig` (31, `tagSignature`),
`data-studio-nested="1"` (38); layouts can mark text with `data-studio-prop="key"`. `describe()`
(`useSelection.ts:443-481`) turns an element into a `StudioTarget`, verifying the hint with
`resolveRange(content, hint, signature)` (`client/md/locate.ts:38`), which returns `null` rather than guess:

```ts
// client/md/locate.ts:17-34
export interface Signature { kind: TargetKind; tag?: string; sig?: string; text?: string; nested?: boolean }
```

After a write the range can shift; `reselect(hint, kind, tag)` (useSelection.ts:291) picks the nearest
same-kind/same-tag element to the old start line. So a bridge must re-publish selection on every change
and should treat ranges as ephemeral.

Props schema, classes, pos, rotation and animation are NOT on the selection. Each panel derives them
from `context.content()` + `selection.range` with pure functions:

new Markdown with `client/md/*` and posting it through Slidev's own endpoint.

`StudioDock.vue` holds a `panels` map (13-20) and renders `<component :is="current.component" />` (49) chosen by

## 5. Inline text editor

`client/ui/InlineEditor.vue`, driven by `editing` (state.ts:29), which is set by double click
(useSelection.ts:214-243, requires `range` or `prop`) or `editText()`. The decision is in `watch(editing, ...)`
(75-194). Three in-place modes plus one fallback:

1. `prop` (89-114): a `data-studio-prop` element; plain string written with `setFrontmatter({ [key]: text })`.
2. `container` (140-151): the parent of the block, if every child is mapped with consecutive ranges
   (`containerOf`, 214-238) and `canEditContainer(runSource, el, verbatim)` round-trips exactly.
3. `block` (175): `blockShape(source)` is non-null and `canEditVisually(source, element, shape)` round-trips.
4. `html` (177-185): otherwise, if `replaceInnerHtml(source, tag, element.textContent, '')` finds the element's
   tag exactly once in the source with the same text, the words are replaced inside the raw HTML.
5. Otherwise `mode = 'markdown'` (187): the block's Markdown in a textarea instead of in place.

```ts
// InlineEditor.vue:175-187
const blockFits = !!shape.value && canEditVisually(source, element, shape.value)
if (heldKind === 'block' && !blockFits) {
  const tag = element.tagName.toLowerCase()
  const was = element.textContent ?? ''
  if (replaceInnerHtml(source, tag, was, '') !== null) { heldKind = 'html'; htmlTag = tag; htmlWas = was }
}
mode.value = heldKind === 'container' || heldKind === 'html' || blockFits ? 'visual' : 'markdown'
```

The styled-span refusal is in the serialiser, `client/md/inline.ts`:

```ts
// inline.ts:108-116
const TRANSPARENT = new Set(['span', 'font'])
const OURS = /^data-studio-/
function isPlain(el: InlineElement): boolean {
  return [...el.attributes].every(attr => OURS.test(attr.name))
}

// inline.ts:152-170 (inside serialiseInline, 130-181)
if (TRANSPARENT.has(tag)) {
  if (!isPlain(el))          // a span/font with any non-studio attribute (class, style) => refuse
    return null
  ...
}
const mark = MARKS[tag]
if (!mark)                   // any tag not in MARKS (strong b em i s del strike code u a img br) => refuse
  return null
if (tag !== 'a' && !isPlain(el))   // a mark carrying attributes => refuse
  return null
```

And the round-trip checks that turn `null` (or any mismatch) into "not visual":

```ts
// inline.ts:380-392
export function canEditContainer(source, root, verbatim?): boolean {
  const written = serialiseContainer(root, verbatim)
  return written !== null && plain(written) === plain(source)
}
export function canEditVisually(source: string, root: InlineElement, shape: BlockShape): boolean {
  const written = serialiseBlock(root, shape)
  return written !== null && plain(written) === plain(source)
}
// plain() 395-400 ignores backslash escapes and whitespace runs only
```

Other refusals in `blockShape` (inline.ts:40-64): a multi-line heading (46); a list whose lines are not all
items (56-57); a "paragraph" whose first line starts with `<`, backtick, `|` or `:` (61-62):

```ts
if (/^\s*[<`|:]/.test(first) || /^\s*$/.test(first))
  return null
```

So a Markdown paragraph such as `Hello <span class="text-red-500">world</span>` is refused visually (the span
has `class`), the container path fails for the same reason, and the html fallback fails because the clicked
element is the `<p>`, which does not appear in the Markdown source (`spansOf` in `client/md/html.ts:52-73`
finds no `<p>`; it also refuses nested same-name tags and `replaceInnerHtml` refuses unless exactly one match,
html.ts:96-98). Result: the textarea fallback, not in-place editing. Inline HTML inside a paragraph is not
annotated either (`annotateTokens` skips tokens without `map`, markdown-source.ts:153), so the span cannot be
selected on its own.

If a visual edit cannot be serialised at apply time, `apply()` reports
"That edit could not be written back as Markdown, so nothing was changed. Edit it as Markdown instead."
(InlineEditor.vue:389-392) and writes nothing. In visual mode the editor makes the slide's own element
`contenteditable` (`hold`, 284-323) and restores its `innerHTML` on release (326-335). Paste is forced to plain
text (273-281). Escape and Ctrl+Enter apply; a pointerdown outside applies (582-592).

## 7. How Studio is enabled

- It must be in Slidev's addon list: headmatter `addons: [slidev-addon-studio]` or the closest `package.json`
  `"slidev": { "addons": [...] }` (README 23-40). The playground uses `addons: [.]`.
- Studio has no env var or config switch of its own. The only `process.env` read is `STUDIO_QA_URL` in tests.
  Its headmatter config is `studio: { annotate: 'all'|'html'|'off', hideComponents: string[] }`
  (plugin.ts:159-168). It turns itself off for `editor: false`, build/export, print, `?embedded`, and the
  notes viewer.
- Slidev 53's resolver (`@slidev/cli/dist/serve-*.mjs:728-743`, `resolveOptions` 1018-1037) builds
  `addonRoots` only from: headmatter `addons` (after theme `slidev.defaults` are merged, which headmatter
  overrides), the closest `package.json`'s `slidev.addons` (`getRoots`, resolver-*.mjs:271-288), and,
  recursively, each addon's own `package.json` `slidev.addons`. Entry options carry `theme`, `download`,
  `routerMode` only. There is no `--addon` CLI flag or env var. Addon names may be absolute paths (`/abs/...`)
  or relative (`./x`, `@/x`) (resolver-*.mjs:230-232).
- Ways to enable without touching the deck's .md: (1) a `package.json` with `slidev.addons` as the deck's
  closest package.json (this edits or adds a project file); (2) a wrapper addon or theme whose `package.json`
  lists Studio in `slidev.addons` (addon) / `slidev.defaults.addons` (theme, but deck headmatter `addons`
  replaces it); (3) launching Slidev through its Node API and adding Studio's root to `addonRoots`/`roots`
  after `resolveOptions`. Slidev also derives `utils`, setups and the merged `vite.config.ts` from roots, so
  this needs care; untested.

## Surprises and risks

- `?embedded` in the URL disables Studio entirely (`global-top.vue:17`; Slidev `useNav.ts:288`
  `query.has('embedded')`). The desktop web view must not load the deck with `?embedded`.
- `studioOpen` defaults to `false` (persisted per origin in localStorage) and gates every canvas listener and the
  canvas RAF loop. The bridge must open it, and `E` can close it again.
- Every slide add/duplicate/delete/move, and every change under `components/` or `layouts/`, triggers a server
  `full-reload`. The bridge must re-handshake on load, and undo history is lost.
- Much of the edit logic is panel-local `<script setup>` code (Inspect setPos/setProp/classes/raw edit,
  Animate apply/disable/motion incl. list-item retargeting, Layout coerce/hide, Slides `run()` post-processing,
  Components/Assets insert/place). It needs extracting before a bridge can share it.
- No select-by-range API; no command serialisation (`busy` is never read).
- Thumbnails and previews are live Vue renders inside the dock and cannot be reused by native panels.
- Notes edits bypass undo history.
- package.json repository/homepage point at the upstream (BobTheShoplifter), not the fork.
