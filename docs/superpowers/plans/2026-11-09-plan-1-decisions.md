Copied from the build ledger on 2026-11-09, when plan 1 finished. Plan 2 should read the deferred items first.

## Rulings

- Setup: Ruling: APP work happens on branch `plan-1` in APP's own checkout, not a separate worktree. The repo is new, holds only docs, and the plan's absolute APP path stays valid. — cost if wrong: none; a later worktree can be cut from `plan-1`.
- Ruling: T8's workspace `Cargo.toml` lists only `crates/protocol`. T9 adds `crates/sidecar` and T11 adds `crates/app` to `members` when they create them. — Cargo refuses a workspace whose members are missing. — cost if wrong: none; it's the same end state.
- Ruling: T10's fixture talk carries no code. The box is `<div v-drag pos="100,100,200,120" class="box">Box</div>` on slide 2, styled by a top-level `style.css`. There is no `components/` folder. T14 checks the label Studio shows for that `<div>`, and the saved `pos="140,100,200,120"`. — The spec's starter talks must not trigger the trust question, and a hang in the dev-home check would block every later task. Trust is covered by T7's and T12's tests. — cost if wrong: the hand check never sees a component selection; plan 4's component work covers that.
- Ruling: T7's e2e test passes `--trust-code` if SP's `testdata/deck` counts as code, so it reaches `ready` without an interactive answer. The trust flow itself is covered by T7's unit tests. — cost if wrong: none.
- Ruling: T14 step 1 item 4 runs SP's own `dist/linux/stagepack serve` with no `--addon`, which is plain Stagepack's runtime. — cost if wrong: none.
- Ruling: Task 1 step 4's hand check of a code-block selection moves to Task 4's smoke test as an extra check: clicking a code block posts `selection` with `kind: 'code'` and a non-null range. The temp copy gets a fenced block if the playground has none. — A subagent can't press E and look at a browser, and Task 4 adds the browser driver anyway. — cost if wrong: a Slidev 53 fence-annotation break is found in Task 4 rather than Task 1, with Tasks 2 and 3 already built on top. Neither touches fences.
- Task 1: Ruling: STUDIO's devDependencies @slidev/cli, @slidev/client and @slidev/types are pinned exactly to 53.0.0, not ^53.0.0. The caret resolved 53.1.0, and the editor's runtime pins 53.0.0 (spec: the editor uses Stagepack's runtime, Slidev 53.0.0), so the tests must run on what ships. — cost if wrong: one line to loosen later.
- Task 2: Ruling: the plan's `<X v-drag pos="…">` syntax is wrong for Slidev and Studio. A positioned element is written either as the `v-drag="x,y,w,h"` directive, or as a `<v-drag pos="x,y,w,h">` wrapper (`formatPos` 'attr' and 'prop'). Task 2's test builds `<Shape v-drag="120,80,200,_"` over the range. Task 10's fixture box becomes `<div v-drag="100,100,200,120" class="box">Box</div>`, and Task 14's saved-file check looks for `v-drag="140,100,200,120"`. — Studio's `readDrag` reads only those forms, and the plan's form would never be positioned. — cost if wrong: none; it's the real syntax.
- Task 3: Ruling: the error texts "Select an element first." and "This element is not freely positioned." become exported constants in client/bridge/protocol.ts (NO_SELECTION, NOT_POSITIONED), which the dispatcher uses, so the wording lives in one place. — cost if wrong: none.
- Task 3: Ruling: the review's Minor 1 (a throw from `post` rejects the queue, so every later command is skipped without a word) is re-graded to Important and enters the fix round. By effect, the editor would stop responding to every command for the rest of the page's life. — cost if wrong: a few lines.
- Task 4: Ruling: the playground's Shape is in the flow (`<Shape name="hexagon" :size="150" … />`), so the smoke sends `free-position` (expects ok + edited + a v-drag in the file) before `set-pos`. The temp copy also gains a slide with a fenced code block for the code-selection check moved from Task 1. The expected count becomes "bridge smoke: N checks passed", with N whatever the script runs, at least 8. — cost if wrong: none.
- Task 5: Ruling: the review's Minor 1 is re-graded to Important and carried into Task 7, which consumes AddonLaunch. The finding: an existing preload file is trusted by name alone and the temp file is never synced, so a crash can leave an empty preload that silently disables the editor addon forever. In Task 7, AddonLaunch syncs the temp file and, on the fast path, compares the file's bytes with the embedded preload and rewrites it when they differ. By effect, a rare crash would leave the editor permanently unable to edit, with no error. — cost if wrong: about 5 lines.

- Task 7: Ruling: a talk opened with no code counts as allowed this session, so if a save adds code (which only the person editing can do), the new hash is remembered. — The person authored that change in their own editor, and asking them on their next open whether to trust their own edit would be noise. Code arriving from elsewhere (a changed file on disk) is caught by the conflict check, not trusted. — cost if wrong: a talk a person edited to add code opens without the question for them; others' machines still ask.
- Task 7: Ruling: the e2e test keeps the `e2e` build tag like the rest of test/, and its run command is `go test -tags e2e ./test/ -run ServeE2E -v`. The brief's untagged command was a plan slip. — cost if wrong: none.
- Ruling: Task 8 (APP, the protocol crate) starts while Task 7 (SP) is in review. They share no repo, files or interfaces (Task 8 consumes only STUDIO's Task 2 fixtures), so the "no parallel implementers" rule, which exists to prevent conflicts, isn't at stake. Task 9, which consumes Task 7's event shapes, waits for Task 7 to complete. — cost if wrong: none; a Task 7 fix can't touch APP.
- Task 10: Ruling: check-dev-home.sh also proves Studio loaded, via GET /@studio/catalog returning JSON with `components`, and dev-home.sh is idempotent (it re-copies Studio after the rsync). — A serve that reaches ready without Studio would pass the brief's check, and every later task would build on a missing editor. — cost if wrong: none.
- Task 10: Ruling: the fixture's package.json also lists "@slidev/cli": "^53.0.0" in dependencies, because stagepack pack refuses a project without it. It isn't installed and isn't code. — cost if wrong: none.
- Task 11: Ruling: the visual part of step 5 (Studio's toolbar absent, the selection outline on click) folds into Task 14's hand check, which the owner does. The implementer verified programmatically that the page's ready, selection and history reach the shell, and that queued commands flush in order after ready. — cost if wrong: a visual bug found at Task 14, not Task 11.
- Task 11: Ruling: gpui-fast resolves to 0.1.13, because 0.1.14 needs gpui-pre =0.3.12 and kit pins =0.3.11. That's consistent with the global constraint. — cost if wrong: none.
- Task 12: Ruling: the brief's "Saved sets dirty = false" is refined. The document counts Edited messages, records the count when a save is sent (a FIFO for saves in flight; Conflict and SaveFailed pop too), and Saved sets dirty = (edits != count at send). Save-then-close only closes when that leaves the talk clean. — An edit landing during a save must not show as saved, or the next close drops it without asking. — cost if wrong: a dot that lingers after a save, erring safe.
- Task 12: Ruling: the review's Minor 1 is re-graded to Important. A Failed state while serve is still running, from a protocol error, an unreadable line or a non-fatal error, disabled the close prompt, so dirty edits were deleted without a word. Closing now always prompts when dirty and the sidecar hasn't stopped, also in Failed, and Save still works there. — cost if wrong: one extra prompt in a broken session.
- Task 12: Ruling: the review's Minor 3 (Ctrl+S does nothing while the page has keyboard focus) enters the fix round. The brief requires "Ctrl+S saves", and in an editor focus is almost always in the canvas. The approach is a gtk key-press hook on the WebKit widget. If it can't be done reasonably in the app, the implementer reports and it moves to plan 2. — cost if wrong: a few hours.
- Ruling: every cargo command in this plan runs through scripts/cargo-safe.sh, in its own scope (MemoryHigh 14G, MemoryMax 18G, 6 jobs), and dependencies build without debug info. — systemd-oomd killed the whole Claude app at 12:30:42 on 2026-11-09 during Task 12's fix round; builds run inside the app's scope, so the app is what got killed. — cost if wrong: slower builds.
- Ruling: synthetic keyboard or mouse input never goes to the owner's real display. The Ctrl+S hand check runs in a nested Xephyr display, or is left to the owner's hand check if GPUI can't start there. — Injected keys land in whatever window has focus. — cost if wrong: Ctrl+S gets checked by hand in Task 14.
- Task 12: Ruling: the implementer's two deviations stand. The re-review checked both. — cost if wrong: one extra wait, with Close Anyway as the way out.
- Task 14: Ruling: the hand check uses the debug build through scripts/cargo-safe.sh run, not --release. A release GPUI build is a long, memory-heavy compile that tests nothing extra here. — cost if wrong: none for this check.
- Task 14: Ruling: corrects my own Task 2 and Task 10 rulings, which were wrong. Slidev's directive form is `v-drag="[x,y,w,h]"`, with brackets; `<v-drag pos="x,y,w,h">` is the wrapper form. - Task 13: Ruling: reopened for one fix. After Undo from the title bar, the still-focused X field kept 140 with the box back at 100, and Enter would re-apply it. A focused field is now left alone only while it holds text the person typed and hasn't committed; after Enter it follows the page's echo. — The "don't fight the typist" rule was too broad; a stale number that can move the box back is the failure it was meant to avoid. — cost if wrong: a typed value replaced by an echo in a rare race.
- Final: Ruling: C1 is fixed by claiming in every home: serve's own, the default per-user install, and any --peer-home, using the normal record format. An installed older Stagepack then finds the live record and hands over, with no change to it. — The reviewer's shared per-user folder wouldn't reach installs already on people's machines. — cost if wrong: an extra record per open.
