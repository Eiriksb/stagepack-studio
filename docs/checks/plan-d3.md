# Plan D3: what ran, and what to check by hand

The run was on the `plan-d3` branch, starting from commit fde7fb3, on a 16-core Linux laptop, with Rust 1.98.0, in a release build, on 2026-11-17. It found three things to fix, fixed in three commits with a test each, 1b82956, 0db5552 and b318d16. The worst of them edited the wrong thing: with the keyboard in the list of slides, Delete on a shape just put on the slide took the whole slide away. The review of the run found three more ways to the same, fixed in 4afa31c (see *After the review*). What was seen again in the window on the release build with the fixes is said under *Again with the fixes* and *After the review*; the other paths each fix touched were checked by headless tests only. The branch hasn't been pushed or merged yet. Nothing here has run on Windows.

## The nested display

The run used a nested X display (`Xephyr :83`, 1280x800, the default framebuffer, no window manager). The display's root is 24 planes deep and stored as 32 bits a pixel, and the screenshot helper read the bits a pixel from each picture's own header, as D2's did, so no screenshot was squeezed. The app window measured 1,280 by 800 and sat 2 pixels in from the left, so the rightmost 2 pixels were off the screen; every click landed where the screenshots showed it. The display draws in software, so the timings say nothing about a real GPU. The run's first launch of the app went to the desktop's own display for a few seconds, as the launch script took the session's display when one was set. The scratch `XDG_*` folders were set for that launch too, by the same script; the window was killed at once, nothing in the talk was changed, and nothing in the real data folders (`~/.local/share/stagepack-studio`, `~/.cache/stagepack-studio`) is newer than 2026-11-09. Every later launch named the nested display on the same command line.

## Real-window check on Linux

The app was the release build, with `XDG_DATA_HOME`, `XDG_CONFIG_HOME`, `XDG_CACHE_HOME` and `XDG_STATE_HOME` set to scratch folders, so the working copies and caches went there and not to the real data folder, and `STUDIO_BUNDLE` set to the compiler bundle in `target/bundle`. The talks were scratch copies of `fixtures/showcase`, `fixtures/components` and `fixtures/show` outside the repository, and a packed talk made from the showcase. The keyboard was the nested display's own US layout. Key presses, clicks, the wheel and window sizes went in through the X test extension, from a small program written for the run. The same program:

- **dropped files** with the X drag-and-drop protocol: it took the X selection for the drag, sent the window the messages a file manager sends (enter, position, drop) with the file as a `text/uri-list`, and answered the window's request for the list. The window accepted each drop and said it was done. No real file manager was used.
- **owned the clipboard** as "another program", giving a picture as `image/png` (2.6 KB, so no transfer in parts) or plain text.

The system's dialogs can't be shown on the nested display. *Picture* on the Insert tab, *Choose file…* in the panel, Open, Save As and Export weren't pressed. Pictures came by the drop above and by the clipboard instead. A packed talk was made with the engine's `pack_folder`, and the talks were exported with `run_export`, the code behind the Export menu, both from a scratch test that was not committed. Every result below is from a screenshot that was looked at. They are under `target/check/d3-run/`, which is not committed.

What looked wrong, and was fixed:

- **Delete took the whole slide away.** With the keyboard in the list of slides, as after clicking a slide there and then *New slide*, a shape put on the slide from the Insert tab was selected, outline, form and all, but the keyboard stayed in the list. Letters typed went nowhere, and Delete took the slide, with everything on it, away; Undo brought it back. That was seen in the window for a rectangle. With an inspector field holding the keyboard, a callout put on the slide didn't take the letters typed next either, which went nowhere; Delete there edits the field's text, not the slide. The headless tests written for the fix showed the slide taken away for an icon, a chart from the palette, and a picture dropped or pasted, as for the rectangle. A thing put on the slide now takes the keyboard. The headless tests had always started with the keyboard on the slide. (1b82956)
- **A click in the list of slides kept the thing shown as selected.** A shape selected, then its slide clicked in the list, still showed its outline and form and *Shape selected*, while Delete took the slide away, as the list had the keyboard. A click in the list now lets go of it. (b318d16, since folded into the rule of 4afa31c)
- **A missing component was called pictures.** A slide pasted from another copy of the app, showing a component this talk didn't have, said *Some pictures on the pasted slide aren't in this talk.* It now says *A component on the pasted slide isn't in this talk.*, a missing picture still says pictures, and both together say both. (0db5552)

What looks wrong and wasn't changed:

- **An icon's Size and its Width and Height are separate fields.** *Size* set to 200 drew the icon at 200 over its 128 by 128 box, while the outline, and what a click on it reaches, stayed the box. The tag is written with both, `size="128"` and `w="128" h="128"`.
- **A colour field's *None* reads as its value.** The swatch and a small *None* button beside it read as *Fill: blue, None*. An outline that isn't set shows a white swatch, as D2's automatic colour does.
- **A talk's component put on the slide at its fixed size stretches its rows.** The Callout, 640 by 360 from the palette, drew its title at the top and the words typed in it at the bottom of the box: the engine lets each row and column in a component take the room there is. In a place on a slide, the words sit under the title.
- **The selection line is thin and grey**, and hard to see on a grey or busy picture.
- **A rounded rectangle's corners are small** at the slide's scale, and hidden under the selection line when it's selected.
- **In the PowerPoint file, drawn by LibreOffice,** the callout's tail sits in the middle of its bottom edge, where the slide has it at the left, and the arrow's head is smaller. Desktop PowerPoint wasn't tried.
- **A text box being typed in shows no edges** once its first letter is typed; the dashed outline goes with the pending box.
- **A notice still shrinks the slide.** *There is no component called Score*, the engine's notice, shows above the status line, and the slide moves up by a line while it's there.
- **New slide after a slide ending in a tag writes its `---` straight under the tag**, as `<Picture … />` then `---`, and a slide pasted as plain text writes `---` then its first line with no blank line between. Both read back as meant; it's how D2's New slide and paste write, seen now that slides end in tags.
- **The Table group on the Home tab is past the arrow** at 1,280 pixels while a cell has the caret (known from Task 10). The panel has the same tools.
- **The text box's form reaches below the window** at 800 pixels high, so *Turn* needs the panel scrolled.
- **The window can't be narrower than 1,024 pixels**, and the form panel always takes 300 of them, also with nothing selected. The status line always keeps one line's height, so the slide is a line shorter than it could be.

## After the review

The review of the run found that Delete could still take the whole slide while a thing on it showed as selected, by three ways the fixes above didn't reach: Undo or Redo pressed with the keyboard in the list of slides brought a thing back selected while the list kept the keyboard; a press on a row moved more than 2 pixels starts a drag, which drops the click that let go of the selection; and a press on the empty part of the list, below the rows, gave the list the keyboard. 4afa31c makes it one rule: a thing shows as selected only while the list hasn't the keyboard. Any press on the list lets go of the thing selected, and so does the list taking the keyboard by any other route, as the window next draws; a thing that becomes selected while the list has the keyboard takes the keyboard for the slide. Headless tests cover Undo and Redo from the list then Delete, a row moved a few pixels, a press below the rows, each of those three with a thing selected before and with one selected after by Undo, Redo and a paste, a thing pasted while the list has the keyboard, and Ctrl+D from the list (the slide) and from the slide (the thing). The rule didn't cover typing: a press below the rows, or a row moved a few pixels, gave the list the keyboard with the caret still drawn in the text, or a new text box still waiting, and Backspace or Delete took the slide. Since 091ce38 the list taking the keyboard also ends the typing on the slide as Escape does, so while the list has the keyboard nothing on the slide is selected, nothing is being typed and no text box waits. Headless tests cover the three ways the mouse gives the list the keyboard with a caret in a region's text, in a region rubbed out, in a shape, in a table cell and in a waiting text box. This was not seen again in the window.

In the window, on the release build with 4afa31c, on a scratch copy of `fixtures/show`: a rectangle deleted, its slide clicked in the list and Ctrl+Z brought it back selected with the slide holding the keyboard, and Delete then took only the rectangle, leaving 3 slides. A rectangle selected, then the first row pressed and moved 7 pixels before letting go, showed nothing selected. A rectangle selected, then a press on the list below the three rows, showed nothing selected. The screenshots are `r1-01` to `r1-05b` under `target/check/d3-run/`.

## Known after the run

Found in this run and not changed are under *How it looks*. These are known from the plan's ledger, and weren't changed:

- **Load-sensitive timing tests** could fail when the whole suite ran on a loaded computer, and passed run alone. The final fixes loosened them, each still below what it guards against (the hanging-components slide least so: 8 s against at least 10 s if its guard broke): `a_schema_that_never_returns_is_stopped` from 30 s to 120 s, the palette's opening from 250 ms to 1 s, D2's paste-refusal margin from 50 ms to 250 ms, and the engine's hanging-components slide from 3 s to 8 s and many-times-placed content from 2 s to 6 s.
- **Slides and their Markdown:** notes written as `> a|` before a table make the table read as a paragraph. A fence left open at one to three columns inside a list item swallows the next slide break, as on `main`. A lone carriage return in inserted text is written as typed. Two or more blank lines after a slide's opening lines leave two blank lines before typed text. Removing an attribute from a tag spread over lines inside a quote removes one space. On an empty two-column slide with notes, text put in the right column has no blank line before `<Notes>`.
- **Picking:** within one layer, a thin line's slack can outrank a small thing over it, and an overlapping quote or mixed text could be taken as a thing.
- **Files:** a different file appearing on disk at an added picture's name makes each save fail, and holds up every other unsaved edit with it, until the picture is taken off the slide or the other file is renamed or moved; adding the picture again doesn't help, as it's given the same name. Save As to another place works meanwhile. Bringing changes back can drop a kept file without a word on a clash of names, and gives up on two clashes whose new names chain. If bringing back is refused after the files came, they stay added. A kept file is judged by its length alone, a file kept with nothing using it stays 30 days, and a failed keep isn't tried again. Reading and decoding a picture happen on the window's thread, so a large one freezes the window for 1 to 3 seconds, and a large TIFF can take about half a gigabyte for a moment. Copy and paste of up to about 96 MB do too. Files from a refused insert stay in memory for the session. Two copies of the app on one folder don't know of each other.
- **The panel:** every *Choose file…* button has the same id; the keyboard can be left on a field that was taken away; the panel is drawn again on every keystroke on the slide; a colour being dragged is dropped if a build finishes or Save As moves the talk meanwhile; a panel first shown in a narrow window keeps its narrow width when the window grows. A comma is the decimal mark, so `1,500` and `1.000` read as 1.5 and 1. A hex colour drops its alpha.
- **Text boxes:** *Text box* is offered on a slide where nothing can be written, and each key then says the plain refusal. A first character that's invisible (zero-width joiners, tag characters and the like) writes a box that looks empty. A text box can't start with a blank line or a space, and since the final fixes neither can the text first typed in an empty shape, box or component: a space typed on a selected shape writes nothing.
- **Icons:** the picker has no scrollbar, and its cells can't be reached by the keyboard, so Enter takes the first match. A refused pick is dropped without a word.
- **Tables:** a cell holding only a no-break space has its padding changed by typing; inline code with a `\` before a `|` in a cell can't be typed in; typing anywhere on a slide holding a full 20 by 51 table takes about 60 to 70 ms a key; within the plan's 8 ms up to about 8 by 13. The sentence for an icon in a cell ignores a box's turn. With a table selected and no caret, only *Row below* and *Column right* work, adding at the end.
- **Components:** aligning a selected component that takes content writes `align` on its tag; a table inside such a component can't be typed in; the palette's one-second budget can run about 250 ms over. A pasted component's build is trusted by the hash the clipboard gives, as a talk's own build index is trusted when it's opened.
- **Selection:** after a reload, the selection can move to a neighbour with the same bytes. A press exactly on a text's left edge can miss it.
- **Pictures in:** a drop, a paste or the dialog takes at most 20 pictures, and says *Only the first 20 pictures were added.* If the dialog itself can't be shown, the window says *The file chooser couldn't be opened.* A big picture is read and decoded on the window's thread, so the window can freeze for a second or more.
- **Numbers:** in a number field, `1,000` and `1.000` both read as 1, as the comma is the decimal mark.
- **More on text boxes and tables:** a new text box can't start with a blank line or a space. Typing in a very large table (20 by 51) is slow. After a table tool is refused, the caret may have left its cell. A hand-written cell of one space, emptied, comes back as two spaces.
- **More on files:** if opening a packed talk again fails after it's saved, the save is still made and says *The talk was saved, but couldn't be read back. Close it and open it again to be sure of it.*; the next save starts from the build index just written, so no entry is lost. A picture added in a session is read from the talk's own files once a save has written it, as the talk's other pictures are, so one changed on disk after that shows after the next save or reload. A change made outside the app is taken as a conflict when the only unsaved thing is an added picture. Several sentences about clashing file names overwrite each other, so only the last is seen.

## The final review

After the run, the whole branch was reviewed once more, from 2c39d20 to 429488c. A random editing session of 51,000 steps over everything this plan added, on five hand-written talks, found no real problem: undoing everything gave the first text back exactly, and redoing gave the last. 270 runs of inserting, undoing, deleting, saving both ways, killing and recovering found none either. Shapes with words, a text box, a table, an icon and a chart all reached the PowerPoint file as themselves. It found three things that mattered, and they were fixed in one wave of ten commits, 091ce38 to fb65bcc, each with a test that failed before its fix:

- **Backspace took the slide while a caret showed in text.** A press on the list of slides let go of a selected thing but left the typing going. A press there now ends the typing as Escape does. (091ce38)
- **The Home tab's bin said only *Delete*** and took the slide while a shape showed as selected. The slide tools now say *Delete slide* and *Duplicate slide*. (6f6125c)
- **A picture added in the session kept being read from memory after it was saved**, so a change to its file never showed and an export differed from a fresh open's. It's read from the talk once saved. (5319dd1)

The wave also made a space typed on a selected shape write nothing, filled the timing test's tables with words (the table timings above are the corrected ones), made the picture dialog say when it couldn't be shown and take 20 pictures at most, gave the timing checks room for a loaded computer, pinned the fence rule with two tests, and made a packed talk that was saved but couldn't be read back count as saved.

At fb65bcc, `scripts/cargo-safe.sh test --workspace` passed: 1,862 tests, 0 failed, 13 ignored, and clippy gave no warnings. The window wasn't run again after the wave, so its fixes have been seen in tests only. A second reviewer then checked the wave and approved it with notes.

One finding that mattered was left by the check of the wave, and the owner asked for it to be fixed before the merge. **A right-click on a slide in the list, with a shape selected or being typed in, left the shape showing as selected while the list had the keyboard**, and Delete or Backspace then took the slide. A row's menu keeps a right press from reaching the list, so the row now lets go of the selection itself (e6ba2a7). The tests of the keyboard rule take a right-click as a fourth way to the list; three of them failed before the fix. A reviewer approved it with notes: a long press on a touch screen opens the menu by another route and isn't covered. At e6ba2a7 the workspace passed again, 1,862 tests, 0 failed, 13 ignored, and clippy gave no warnings. This fix too has been seen in tests only.

Known after the final review, and not changed:

- **Ctrl+D with the keyboard in the notes duplicates the slide** while a thing shows as selected. **Left, Right and the Page keys with a thing selected change the slide**; they don't move the thing.
- **The Home tab is wider.** At 1,280 pixels Undo and Redo are behind the arrow at the row's end, and the row fits whole from about 1,410.
- **A slide with sixty things** is at the 8 ms budget for a keystroke. **A hand-written table near 10,000 cells** opens at once and then takes over half a second a key.
- **Save As to a packed talk that is written but can't be read back says the save failed**, though the file is there.
- **Typing at the very start of a selected table's first cell, or the end of its last, lets go of the table.**
- **The table timings were measured through the document**, not in the window.
