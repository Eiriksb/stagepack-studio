# Plan D3: what ran, and what to check by hand

The run was on the `plan-d3` branch, starting from commit fde7fb3, on a 16-core Linux laptop, with Rust 1.98.0, in a release build, on 2026-11-17. It found three things to fix, fixed in three commits with a test each, 1b82956, 0db5552 and b318d16. The worst of them edited the wrong thing: with the keyboard in the list of slides, Delete on a shape just put on the slide took the whole slide away. The parts of the run each fix touched were run again on the release build with the fix. The branch hasn't been pushed or merged yet. Nothing here has run on Windows.

## The nested display

The run used a nested X display (`Xephyr :83`, 1280x800, the default framebuffer, no window manager). The display's root is 24 planes deep and stored as 32 bits a pixel, and the screenshot helper read the bits a pixel from each picture's own header, as D2's did, so no screenshot was squeezed. The app window measured 1,280 by 800 and sat 2 pixels in from the left, so the rightmost 2 pixels were off the screen; every click landed where the screenshots showed it. The display draws in software, so the timings say nothing about a real GPU. The run's first launch of the app went to the desktop's own display for a few seconds, as the launch script took the session's display when one was set; it was closed at once with nothing changed, and every later launch named the nested display.

## Real-window check on Linux

The app was the release build, with `XDG_DATA_HOME`, `XDG_CONFIG_HOME`, `XDG_CACHE_HOME` and `XDG_STATE_HOME` set to scratch folders, so the working copies and caches went there and not to the real data folder, and `STUDIO_BUNDLE` set to the compiler bundle in `target/bundle`. The talks were scratch copies of `fixtures/showcase`, `fixtures/components` and `fixtures/show` outside the repository, and a packed talk made from the showcase. The keyboard was the nested display's own US layout. Key presses, clicks, the wheel and window sizes went in through the X test extension, from a small program written for the run. The same program:

- **dropped files** with the X drag-and-drop protocol: it took the X selection for the drag, sent the window the messages a file manager sends (enter, position, drop) with the file as a `text/uri-list`, and answered the window's request for the list. The window accepted each drop and said it was done. No real file manager was used.
- **owned the clipboard** as "another program", giving a picture as `image/png` (2.6 KB, so no transfer in parts) or plain text.

The system's dialogs can't be shown on the nested display. *Picture* on the Insert tab, *Choose file…* in the panel, Open, Save As and Export weren't pressed. Pictures came by the drop above and by the clipboard instead. A packed talk was made with the engine's `pack_folder`, and the talks were exported with `run_export`, the code behind the Export menu, both from a scratch test that was not committed. Every result below is from a screenshot that was looked at. They are under `target/check/d3-run/`, which is not committed.

## Known after the run

Found in this run and not changed are under *How it looks*. These are known from the plan's ledger, and weren't changed:

- **Load-sensitive timing tests** can fail when the whole suite runs on a loaded computer, and pass run alone: `a_schema_that_never_returns_is_stopped` (a 30 s bound), the palette's 250 ms check, D2's paste-refusal check with 50 ms to spare, and two of the engine's talk-component timings. None failed in this run.
- **Slides and their Markdown:** notes written as `> a|` before a table make the table read as a paragraph. A fence left open at one to three columns inside a list item swallows the next slide break, as on `main`. A lone carriage return in inserted text is written as typed. Two or more blank lines after a slide's opening lines leave two blank lines before typed text. Removing an attribute from a tag spread over lines inside a quote removes one space. On an empty two-column slide with notes, text put in the right column has no blank line before `<Notes>`.
- **Picking:** within one layer, a thin line's slack can outrank a small thing over it, and an overlapping quote or mixed text could be taken as a thing.
- **Files:** a different file appearing on disk at an added picture's name makes each save fail until the picture is added again. Bringing changes back can drop a kept file without a word on a clash of names, and gives up on two clashes whose new names chain. If bringing back is refused after the files came, they stay added. A kept file is judged by its length alone, a file kept with nothing using it stays 30 days, and a failed keep isn't tried again. Reading and decoding a picture happen on the window's thread, so a large one freezes the window for 1 to 3 seconds, and a large TIFF can take about half a gigabyte for a moment. Copy and paste of up to about 96 MB do too. Files from a refused insert stay in memory for the session. Two copies of the app on one folder don't know of each other.
- **The panel:** every *Choose file…* button has the same id; the keyboard can be left on a field that was taken away; the panel is drawn again on every keystroke on the slide; a colour being dragged is dropped if a build finishes or Save As moves the talk meanwhile; a panel first shown in a narrow window keeps its narrow width when the window grows. A comma is the decimal mark, so `1,500` and `1.000` read as 1.5 and 1. A hex colour drops its alpha.
- **Text boxes:** *Text box* is offered on a slide where nothing can be written, and each key then says the plain refusal. A first character that's invisible (zero-width joiners, tag characters and the like) writes a box that looks empty. A text box can't start with a blank line or a space.
- **Icons:** the picker has no scrollbar, and its cells can't be reached by the keyboard, so Enter takes the first match. A refused pick is dropped without a word.
- **Tables:** a cell holding only a no-break space has its padding changed by typing; inline code with a `\` before a `|` in a cell can't be typed in; typing in a 20 by 51 table takes about 13 ms a key to lay out. The sentence for an icon in a cell ignores a box's turn. With a table selected and no caret, only *Row below* and *Column right* work, adding at the end.
- **Components:** aligning a selected component that takes content writes `align` on its tag; a table inside such a component can't be typed in; the palette's one-second budget can run about 250 ms over. A pasted component's build is trusted by the hash the clipboard gives, as a talk's own build index is trusted when it's opened.
- **Selection:** after a reload, the selection can move to a neighbour with the same bytes.
